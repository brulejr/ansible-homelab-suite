# Watchtower Role

Installs and manages Watchtower using Docker Compose.

Watchtower monitors Docker containers and can automatically update them when newer images are available.

## Files

```text
roles/watchtower/
├── defaults/main.yml
├── tasks/main.yml
├── tasks/validate.yml
├── tasks/install.yml
├── tasks/verify.yml
├── templates/docker-compose.yml.j2
├── handlers/main.yml
├── meta/main.yml
└── README.md
```

## Default Variables

| Variable                           |                        Default | Description                                 |
| ---------------------------------- | -----------------------------: | ------------------------------------------- |
| `watchtower_enabled`               |                         `true` | Enables or disables the role                |
| `watchtower_stack_name`            |                   `watchtower` | Docker Compose project name                 |
| `watchtower_container_name`        |                   `watchtower` | Container name                              |
| `watchtower_app_dir`               |  `{{ docker_dir }}/watchtower` | Directory containing generated compose file |
| `watchtower_image`                 | `containrrr/watchtower:latest` | Docker image                                |
| `watchtower_restart_policy`        |               `unless-stopped` | Docker restart policy                       |
| `watchtower_docker_network`        |         `{{ docker_network }}` | External Docker network                     |
| `watchtower_cleanup`               |                         `true` | Removes old images after updates            |
| `watchtower_log_level`             |                         `info` | Watchtower log level                        |
| `watchtower_poll_interval`         |                        `86400` | Poll interval in seconds                    |
| `watchtower_label_enable`          |                        `false` | Restrict updates to labeled containers      |
| `watchtower_rolling_restart`       |                         `true` | Restart containers one at a time            |
| `watchtower_docker_api_version`    |                         `1.52` | Docker API version override                 |
| `watchtower_registry_auth_enabled` |                        `false` | Enables registry auth config mount          |
| `watchtower_registry_config_path`  |                           `""` | Host path to Docker registry auth config    |
| `watchtower_monitor_containers`    |                           `[]` | Optional explicit container list            |
| `watchtower_verify_enabled`        |                         `true` | Enables verification tasks                  |

## Example Inventory

Update all containers managed by the Docker daemon:

```yaml
watchtower_enabled: true
watchtower_cleanup: true
watchtower_poll_interval: 86400
watchtower_label_enable: false
```

Only update selected containers:

```yaml
watchtower_monitor_containers:
  - openwebui
  - ollama
  - plantuml
```

Only update labeled containers:

```yaml
watchtower_label_enable: true
```

When using label-based updates, individual containers need the appropriate Watchtower label in their compose definitions.

## Registry Auth

If private registry access is needed:

```yaml
watchtower_registry_auth_enabled: true
watchtower_registry_config_path: /root/.docker/config.json
```

If the registry credentials are generated by Ansible, keep the source credentials in private inventory using Ansible Vault.

## Running

```bash
ansible-playbook site.yml --limit ai_servers
```

## Notes

This role mounts `/var/run/docker.sock` into the container. That gives Watchtower control over the Docker daemon on the host, so only run it on trusted hosts.
